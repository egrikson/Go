Ты фиксируешь прогресс в тренажёре по Go: проверяешь, что изменилось, обновляешь README и Obsidian, коммитишь и пушишь. Работаешь сам от начала до конца, вопросов не задаёшь — кроме случаев из раздела «Когда остановиться».

## Где что лежит

- Репозиторий: текущая рабочая папка (модуль `gostudy`), ветка `main`, remote `origin`.
- README: `README.md` в корне — таблица «Блок 1 — по темам» (и аналогичные для следующих блоков).
- Obsidian: `C:\Users\egrick\iCloudDrive\iCloud~md~obsidian\vault\Areas\Изучение Go\`
  - `Блоки\Блок N. ....md` — чек-лист тем блока;
  - `Конспекты\...` — конспекты, ищи по названию темы.
- Если папки Obsidian на этой машине нет (например, на ноутбуке другой путь) — шаг 4 пропусти и прямо скажи об этом в отчёте.

## Шаг 1. Синхронизация с GitHub

1. `git fetch -q origin`, затем `git status -sb`.
2. Если ветка отстаёт (`behind`) и рабочая копия чистая — `git pull --ff-only`.
3. Если отстаёт **и** есть локальные изменения — остановись (см. «Когда остановиться»).

## Шаг 2. Разобрать изменения

`git status --porcelain` — найди изменённые и новые файлы. Сгруппируй `.go`-файлы по папкам задач (`block01/<тема>/taskN`).

Для каждой изменённой задачи:
1. `gofmt -l` → если файл не отформатирован, `gofmt -w` (меняет только пробелы и пустые строки — это разрешено).
2. `go vet ./<папка>` и `golangci-lint run ./<папка>/`.
3. `go run ./<папка>` и сравни вывод **буквально** с блоком «Ожидаемый вывод» в шапке файла.
4. Определи статус задачи:
   - **решена** — компилируется, вывод совпал, ограничения из шапки соблюдены (прочитай код и проверь);
   - **не доделана** — работает, но вывод не совпал или нарушено ограничение;
   - **заготовка** — не компилируется, в коде остались `// TODO`.

**Логику решений не трогать.** Разрешено только: `gofmt`, а для недоделанной задачи — добавить в шапку блок `// НЕ ДОДЕЛАНО:` с конкретным списком невыполненных пунктов (формат как в `block01/functions-multi/task3`). Если в шапке уже есть `НЕ ДОДЕЛАНО`, а задача теперь решена — этот блок удалить.

## Шаг 3. README

В таблице «Блок N — по темам» обнови строку темы (или добавь новую):
- 🟢 пройдено — все задачи темы решены;
- 🟡 + коротко, что решено и что осталось (`решены 1–3; 4 — доработать (…)`);
- ⬜ — тема ещё не начата.

Пиши так же коротко, как в соседних строках. Других разделов README не трогай.

## Шаг 4. Obsidian

1. **Заметка блока**, чек-лист тем: в строке темы обнови пояснение после `—` — что закрыто и в какой папке, что осталось. Чек-бокс темы `[x]` ставь, только если тема закрыта целиком (все задачи решены), с датой `✅ ГГГГ-ММ-ДД`.
2. **Конспекты темы**, раздел «Проверить у Claude»: чек-бокс «попросить практику по теме» → `[x]` с датой и папкой задач, если он ещё не отмечен.
3. Текст конспектов, frontmatter (кроме `статус: 🟢 Закрыт`, когда тема закрыта целиком) и «Что запомнить» — **не трогать**.

**Как писать в Obsidian — обязательно:** хранилище синхронизирует iCloud, и при записи через временный файл с переименованием он создаёт копию «<имя> 2.md», а оригинал пропадает. Поэтому:
- до правок сними список файлов: `find "<папка Изучение Go>" -type f | sort > <scratchpad>/before.txt`;
- пиши **на месте**: короткий скрипт на Python (`python` или `python3`), `open(path, "w", encoding="utf-8", newline="")`, с сохранением окончаний строк (`\r\n`, если были). Перед заменой проверяй, что исходный фрагмент встречается ровно один раз;
- после правок сравни список файлов с `before.txt`. Появился «… 2.md» вместо оригинала — переименуй обратно и проверь, что содержимое — твоя правка.

## Шаг 5. Коммиты и пуш

- Добавляй файлы **поимённо** (`git add <пути>`), не `git add -A`. Никогда не коммить `.claude/settings.local.json`, `.env`, бинарники, секреты.
- Логичные коммиты, сообщения по-русски в повелительном наклонении, как в истории репозитория:
  - решения: «Добавить решения задач 1–3 на <тема>»;
  - заготовки: «Добавить заготовки задач на <тема>»;
  - если задача не доделана — вторая строка сообщения объясняет, чего не хватает.
  - README можно класть в тот же коммит, что и решения, к которым он относится.
- Каждое сообщение заканчивается строкой:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
- `git push origin main`. Хуки не пропускать (`--no-verify` запрещён).

## Когда остановиться и ничего не коммитить

- ветка отстаёт от `origin`, а локально есть незакоммиченные изменения — риск конфликта;
- `git push` отклонён;
- в изменениях есть что-то похожее на секрет (токен, пароль, `.env`).

В этих случаях опиши ситуацию и предложи, что сделать, — сам не разрешай.

## Отчёт

Коротко, по-русски, списками:
- коммиты: хеш и сообщение, запушено или нет;
- по каждой изменённой задаче: статус (решена / не доделана — чего не хватает / заготовка);
- что изменено в README;
- что изменено в Obsidian (или почему шаг пропущен);
- что осталось сделать пользователю.
